Scan, checkpoint or location?

Start with the question. Do you need someone to confirm a step, proof that something passed a point, or where it is right now? Each is a different job. Scans confirm steps, RFID checkpoints prove passage, and UWB location, such as AmIMotion, down to ±10 cm in 3D, shows where work is between those points and how long it waits.

  3. When location adds something

When a scan is right

A scan is a deliberate confirmation of an item or a step. If that is all you need, improve the scanning first.

When a checkpoint is enough

If you only need to know that an item passed a point, test a checkpoint against exactly that.

When location adds something

If work moves between scans and people go looking for it, location answers a new question. It still needs a link to the job and a tested install.

Compare the whole effort

Count anchors, setup, power, network, tag mounting, reassignment, upkeep and exceptions. Compare the cost of useful answers, not hardware prices alone.

Use the same test

Give every option the same scenario and the same measures. Record what each sees, what it misses and how much human effort it needs.
